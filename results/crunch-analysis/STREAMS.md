## Chain semantics observed

- `next_magic_delta = -1` for 487/503 (E2E) and 419/435 (E2): the decoder's
  bit reader consumes exactly one byte into the next stream's magic header
  (bit-buffer over-read), i.e. streams are packed back-to-back. This is why
  the first sequential-chain harness stopped after stream 0; decoding each
  scanned offset independently avoids the artifact. The same over-read,
  applied at end-of-input, is what produces the 20-byte zero-bit padding tail
  documented for `e2_fw-vxWorks` in RECOVERY.md.
- All larger deltas are alignment zeros or *uncompressed* package elements
  interleaved between streams (verified non-stream content: UltraSite32
  version records, `File: *.XIF generated by APC Revision 2.74` data files,
  XML `VersionInfo`/`FirmwareInfo` fragments). No magic-header stream in
  either package failed to decode.

## Decoded content (E2 facts, not E3/SS)

- 97 XML streams per package (help/documentation `<dataroot>` topics and
  config). 94/97 parse as well-formed XML with a strict parser; the other 3
  carry leading `\r\n` before `<?xml` and/or bare `&` in vendor help text
  ("I/O Boards & Controllers") — vendor source quirks, not decode corruption
  (produced == declared, flags clean).
- 406 (E2E) / 338 (E2) binary streams: E2E controller UI screen/application
  definition records (embedded strings such as "Network Setup",
  "Network/Board Setup", "Device Info", "Refrigerants Syslist Extension"),
  8 `APPI`-tagged blobs, misc tables. None are ELF/PE code.
- The two E2 64 KiB-segment streams (`0x8018a`, `0x8818a`, declared 308,280
  each) are two *different* Windows BMP bitmaps (sha256
  `bfe61348…` / `5952a900…`), i.e. display images, not BootROM code.
- 131 output hashes are shared between the two packages; the last five
  streams of each table are identical (same declared/consumed).
- Zero `SFUB` hits across all 942 decoded outputs. Zero Site Supervisor
  content (only unrelated `tunE3`-style tokens). These are E2/E2E
  application resources.

  and `extracted/E2_3.11F02/SysUpdt.tmp` (99,845 B, entropy 7.52): genuine

  No magic anywhere in either file. Status unchanged: opaque (not Crunch).
- `extracted/E2E_4.11F03/bootrom-raw.bin` (566,054 B): probe returns `0x0`;

  visible at file offset `0x45`) immediately preceding the carved updater ELF
